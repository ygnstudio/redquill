# RedQuill 使用指南

> 版本：v1.0.0（2026-09-03，合一正式版）　配套插件：`ygnstudio/redquill`
> 定位：在 Obsidian 里舒服地写中文 md——**通用写作**（粘贴净化、排版体检、写作仪表盘）与**公文排版**（GB/T 9704 红头/版式/docx）合一。普通笔记走通用写作体验；frontmatter 命中公文要素自动切公文模式，可命令手动三态兜底。

---

## 一、安装与启用

1. **BRAT 安装（推荐）**：安装 BRAT 插件 → 添加仓库 `ygnstudio/redquill`
2. **手动安装**：从 [Releases](../../releases) 下载 `main.js`、`manifest.json`、`styles.css`，放入 `<vault>/.obsidian/plugins/redquill/`，在设置 → 第三方插件中启用
3. **双端可用**：通用写作层（净化/八条体检/写作面板）手机、平板、桌面全支持（`isDesktopOnly: false`）；桌面能力——公文排版预览、docx 导出——在移动端自动不出现（能力降级，不干扰笔记写作）。docx 文件可经云同步在手机平板打开查看，渲染效果以桌面 Word/WPS 为准

> 自 v1.0.0 起，RedQuill 为统一主线插件；历史组件 [MDQuill](https://github.com/ygnstudio/mdquill)（通用写作）与 [RedHead](https://github.com/ygnstudio/obsidian-redhead)（公文排版）的能力全部并入、仓库归档留档。旧 redhead / mdquill 插件目录可停用删除。

## 二、两种模式与上下文判定

RedQuill 一个插件、两套能力，按**上下文**自动选边：

| 模式 | 适用 | 触发条件 | 能力 |
| --- | --- | --- | --- |
| **通用写作** | 普通笔记、长文、笔记库 | 无公文要素 | 粘贴净化 / 八条体检 / 一键修复 / 写作面板五卡 |
| **公文排版** | 红头文件、通知、请示等 | frontmatter 含任一 `rh-*` 键（值非空） | 属性表单 / 排版预览 / docx 导出 / 公文体检 / 写作辅助 |

**判定规则**：检查整篇笔记 frontmatter——出现 `rh-agency`、`rh-docNumber` 等 `rh-*` 平铺键（或旧版 `redhead:` 嵌套块）且值非空 → 公文模式。空模板（有键无值）不算，避免新建文件误触发。旧版 `redhead:` 嵌套写法兼容识别。

**手动兜底**：命令「**切换公文模式**」三态循环——`自动判定 → 强制公文 → 强制通用`，会话级即时生效（不写入文件）；切回「自动判定」后按 frontmatter 重新判断。需要跨会话固定时，写/删一个 `rh-` 键即可。

## 三、命令一览

| 命令 | 模式 | 做什么 |
| --- | --- | --- |

| 打开通用写作面板 | 通用 | 右侧栏五卡仪表盘（字数/体检速览/标题树/快捷插入/引导） |

侧栏图标：`file-text` = 排版预览（公文）；`pen-tool` = 写作辅助（公文）；`gauge` = 通用写作面板。

# 第一部分　通用写作层

## 四、粘贴净化

清洗内容（网页/Word/WPS 粘贴最脏的几类）：

- 剥 HTML 全部标签、`<script>`/`<style>`/注释整体剔除
- 行首尾空白剥除（普通空格、全角空格 U+3000、NBSP、制表符）
- 空行压缩：段间恰好空一行（md 段落约定）
- 实体解码（`&nbsp;` `&amp;` 数字实体等）
- html 来源行内连续空白折一空格（Word 空 `<span>` 串、`&nbsp;` 连发残留）

**不做**：不合并行、不改行内文字（专名/数字间空格保留）——粘贴是「排版脏数据规整」，不是改写。公文正文与普通笔记共用同一引擎，行为一致。

剪贴板权限说明：命令式读取剪贴板依赖系统权限。若提示「读不到剪贴板」，直接粘贴后再运行「清洗选区 / 当前段」（该命令不碰剪贴板）。

自动净化粘贴（设置开关，默认关）：开启后编辑器内粘贴带格式 HTML 自动清洗插入；纯文本粘贴直通不处理；无变化也不拦截。保守起见默认关，建议先习惯命令，确实频繁再开。

## 五、中文排版体检（八条规则）

| 规则 | 级别 | 自动修 | 说明 | 示例 |
|---|---|---|---|---|
| repeated-punct | error | ✅ | 重复标点连发 | 「你好。。。」→ 折叠为「。」 |
| punct-mix | error | ✅ | 中文句内半角标点（, . ; : ! ? ( )），含中文标点后接半角（如「）;」） | 「你好,世界」→「你好，世界」；数字/缩写/省略号/范围的半角点不误伤 |
| cjk-latin-space | warn | ✅ | 中文与拉丁字母相邻缺空格（数字除外） | 「用Obsidian写」→「用 Obsidian 写」 |
| bracket-mismatch | error/warn | ❌ | 括号引号配对：中文括号不成对 error；引号疑似未闭合、半角括号不成对 warn（引文跨行可忽略） | 「他说（注意」报 error |
| straight-quote | warn | ❌ | 中文语境出现直引号 " ' | 「他问"你是谁"」建议用“ ” |
| dup-word | warn | ❌ | 疑似叠字笔误（的的/了了/是是/在在…） | 「这个的的问题」 |
| control-char | error | ✅ | 控制字符/零宽字符混入（多来自网页复制） | U+200B 等，一键清除 |
| fullwidth-space | warn | ✅ | 行内全角空格 U+3000 | 行首的删除、行内转普通空格 |

**保护机制**（扫描与修复共用，防误伤）：

- 代码围栏（```…```）内整段跳过
- 行内 code（`a,b`）、裸 URL（https://…）、md 链接（[文](url)）整段跳过
- frontmatter（---…---）整段跳过

修复原则：只自动修「无歧义」类（表内 ✅ 五条）；括号/引号/叠字类只报不修——它们可能是写法风格或引文跨行，交给作者判断。修复按行执行、可 Ctrl+Z 逐行撤销。

## 六、写作面板（五卡）

右侧栏「通用写作面板」实时跟随（200ms 防抖），内容随光标/输入刷新：

1. **字数**：中文 / 非空白 / 总字符 / 段数 / 光标所在行
2. **标点体检速览**：实时全文体检的 error/warn 计数；有则「看报告」弹完整列表，通过则显示「通过」
3. **标题树**：h1-h3 大纲，点击跳转该行；当前所在小节高亮（面板开着时不迷路）
4. **快捷插入**（光标处）：`# 标题` / 表格 3×3 / 引用 / 代码块 / 折叠块（callout）/ 待办项 / 分隔线 / 图片占位
5. **空文档引导**：空笔记时提示从 # 标题写起（不做模板灌输）

# 第二部分　公文排版层

## 七、快速上手（两条路）

> 已有公文文件：直接走下面的 A/B 两条路。**从零起草**推荐先命令「新建公文」生成骨架（选文种 → 输标题，默认机关与当年文号自动就位，见 §九 ①），再回来补属性。

### 路线 A：写作辅助面板 → 公文属性表单（推荐新手）

1. 打开（或新建）一篇 md 笔记
2. 侧栏 `pen-tool` 图标（或命令「打开写作辅助面板」）开右侧栏面板
3. 面板「常用」区点「**公文属性表单**」→ 弹出中文表单，分三组：
   - **版头**：发文机关标志、发文字号、签发人、份号、密级、紧急程度
   - **主体**：主送机关、附件说明、附注、成文日期、署名
   - **版记**：抄送、印发机关、印发时间、印数
4. 填好提交 → 自动以 `rh-*` 英文键写进笔记属性（已有属性替换、其他属性保留）
5. 打开预览即见红头

### 路线 B：手写属性

笔记头部直接写平铺属性（Obsidian 属性面板逐条独立编辑），正文用 `#`（大标题）、`##`（一级）、`###`（二级）、`####`（三级）分层：

```yaml
---
rh-agency: XX镇人民政府文件        # 发文机关标志（红头，不填则无红头；联合行文多机关用 / 分隔，见 §十二）
rh-docNumber: X政发〔2026〕18号    # 发文字号（年份必须用全角六角括号〔〕）
rh-signer: 张三                    # 签发人（上行文才填）
rh-copyNumber: 000015              # 份号
rh-secretLevel: 秘密★1年           # 密级和保密期限
rh-urgency: 特急                   # 紧急程度
rh-recipients: 各村（社区）：      # 主送机关（冒号自动补）
rh-attachments: 1. 实施方案        # 附件说明
rh-notes: （联系人：张三）          # 附注（圆括号自动补）
rh-date: 2026年9月10日             # 成文日期（默认右空 4 字，见 §十四 可调）
rh-signature: XX镇人民政府         # 署名（默认以日期为轴居中，见 §十四 三档对齐）
rh-cc: 县农业农村局、县财政局      # 版记·抄送
rh-printOrg: XX镇党政办公室        # 版记·印发机关
rh-printDate: 2026年9月12日        # 版记·印发时间（自动补「印发」）
rh-printCopies: 30                 # 版记·印数（自动补「印 X 份」）
rh-logo: 附件/机关标志.png         # 机关标志图片（可选，嵌红头）
---
```

> 兼容旧版嵌套写法 `redhead:` 块，无需迁移——两种写法都会被判定为公文模式。

## 八、表格（md 表格语法）

正文直接写标准 md 表格（任务分解表、名单、回执等），预览与 docx 以公文附表样式渲染（0.5pt 单实线全框、列宽均分版心、表头行加粗居中且跨页自动重复）：

```md
| 村（社区） | 责任人 | 完成时限 |
| --- | --- | --- |
| 云溪村 | 张三 | 9月30日前 |
| 桃园社区 | 李四 | 9月30日前 |
```

- **首行 = 表头**：加粗居中；无数据行的表（只有表头）不渲染
- **列对齐**：缺省居中；分隔行写标记可改——`:--` 左对齐 / `:--:` 居中 / `--:` 右对齐
- **表内文字样式**：由预设的「表格（表内文字）」角色控制（设置 → 预设 → 编辑）；公文·标准默认**四号仿宋 14pt**（比正文三号小一号，多列表格更从容），日常·简洁默认 11pt；「加粗」开关 = 整表加粗
- 单元格内 `**加粗**` 等行内标记会自动剥成纯文本（与 docx 一致）

### Templater 弹窗模板

装有 Templater 且启用时，「安装公文模板」会附带「(弹窗)」版本——插入时弹窗输入标题/机关/字号，日期自动填当天。

### 写作提效四件套（v0.11.0 能力，合一后沿用）

**① 新建公文向导**：命令「**新建公文**」弹 16 文种列表（可直接打字筛选，如输「请」定位请示）→ 回车选定 → 弹窗输入标题 → 自动在**当前文件夹**建好 md 并打开：

- 发文机关自动预填——在设置 → **写作**区填「默认发文机关（红头）」（如 `云溪镇人民政府文件`）后，向导建文时写进 frontmatter `rh-agency`（联合行文照旧用 `/` 分隔多机关）；留空则用模板占位「XX镇人民政府文件」待改
- 模板里的占位年份自动替换为**当年**（如 `X政发〔2026〕N号`）
- 同文件夹重名自动递增（`… 2.md`），不覆盖旧稿

**② 「一、」裸序号识别**：正文里直接写「一、总体目标」**不必**手动加 `##`——解析时自动按**一级标题**渲染（黑体三号、顶格），预览与 docx 同源：

```md
一、总体目标          ← 裸写，自动一级标题（黑体）
通过集中整治实现村容整洁。
```

防误伤规则：段首是汉字序数（一~十、多字如「十二」）+ 顿号、但**含句号**的段落仍按正文（如「一、加强领导。各村要成立领导小组……」，是段旨句不是标题）。原有显式写法 `## 一、…` 照常优先，不受影响；三级及以下（`（一）`、`1.`）仍须写 `###`/`####`。

**③ 写作辅助面板**：侧栏「pen-tool」图标（或命令「打开写作辅助面板」）打开右侧栏面板，**跟随光标**实时诊断当前行的公文角色：

- **角色卡**：第 N 行是文件标题 / 一级标题 / 二级标题 / 裸「一、」（提示可升一级）/ 正文 / 表格 / 引用 / 列表，还是手敲空格或全角空格开头的正文（提醒删掉、交给排版自动缩进）
- **序号建议**：扫正文里已出现的一、二级标题，提示下一个该用的序号（一级「三、」、二级「（四）」），避免数错序
- **快捷插入**：点击即在光标处插入 `## 三、`、`### （四）`、`#### 1.`、表格骨架、附件另面 `---` 分隔线
- **常用**：公文属性表单、排版体检、导出 docx，写作时不离开面板直达

### 公文排版体检

对当前笔记做一次国标自查，结果弹窗报告：顶部计数，问题按 **错误（error）/ 建议（warn）** 分级，每条含问题码、说明与 md 行号；点「第 N 行」跳到源码模式对应位置。报告只读——不改正文、不阻塞导出；无问题时提示「排版体检通过」。

| 级别 | 检查项 | 触发示例 |
| --- | --- | --- |
| 错误 | 属性键拼写（unknown-rh-key） | `rh-note` 等不存在/拼错的键（附最近键名提示） |
| 错误 | 发文字号格式（doc-number-format） | 年份缺全角六角括号〔〕 |
| 错误 | 成文日期缺失（date-missing） | 有署名机关而缺 `rh-date` |
| 错误 | 日期早于文号年份（date-before-doc-year） | 成文日期年份 < 文号年份，时序矛盾 |
| 错误 | 版记要素缺漏（colophon-incomplete） | 写了版记但缺印发机关或印发时间 |
| 建议 | 缺发文字号（no-doc-number） | 有红头/成文日期而缺 `rh-docNumber` |
| 建议 | 缺署名机关（signature-missing） | 有日期而缺 `rh-signature` |
| 建议 | 日期非国标格式（date-format） | `2026-9-3` → 建议 `2026年9月3日` |
| 建议 | 附件用顿号分隔（attachment-format） | 多附件建议用 `/` 分隔，正文渲染逐条「附件：」 |
| 建议 | 版记缺印发份数（colophon-copies-missing） | 补 `rh-printCopies` |
| 建议 | 标题层级跳级（heading-skip） | 三级标题前没有二级等 |

三条入口同一引擎：命令面板、预览面板「体检」按钮、CLI `--check`（输出 JSON，有 error 级退出码 2）。

### 附件正文：另面起排（`---` 分隔）

公文附件有两层：**附件说明**（`rh-attachments`，写在属性里，正文下方落款上方渲染）与**附件正文**（内容本身）。把附件正文直接写在正文**之后**，用单独一行 `---` 分隔：

```md
（正文……请认真贯彻执行。）

---

# 附件1：XX实施方案

为落实……制定本方案。

### （一）工作目标
```

- `---` 需独占一行、前后留空行；其**后全部内容归附件区**（正文里就不要再拿 `---` 当分隔线了）
- 导出 docx 时附件区**另起一面**（新节）排布，预览中以虚线「另面 · 附件」提示分页位置
- 附件区首个标题建议写 `# 附件N：标题`——渲染时自动拆成「附件N」标记行（黑体三号顶格）+ 居中标题；多附件时后续 `# 附件2：…` 标题按黑体标题行原样排
- 附件区末尾如仍有版记要素（抄送/印发），版记并入附件区结尾（附件模式自动关闭「版记拆偶数页」，两套规则不叠加）

## 十、发文字号格式

年份必须用**全角六角括号**：`X政发〔2026〕18号` ✔
写错为半角 `[2026]` / `(2026)` 或漏掉年份括号时，导出与表单提交会弹 Notice 提醒（不阻断导出，自行斟酌）。

## 十一、发文字号校验行为

文号格式问题在四处被拦截，同一套规则（年份须全角六角括号）：

| 触发点 | 行为 |
| --- | --- |
| 公文属性表单提交 | 文号半角括号/缺 `〔〕` 时弹 Notice 提醒，不阻断写入 |
| 导出 docx | 同样弹 Notice 提醒（不阻断导出，自行斟酌） |
| 公文排版体检 | 报 error 级 `doc-number-format`（见 §九 体检表），报告可点行号跳源码 |
| CLI `--check` | 输出 JSON 问题清单，有 error 级退出码 2（可接 CI） |

## 十二、版头机关标志：图片（rh-logo）与联合行文

### 机关标志图片（rh-logo）

1. 把机关标志图片（PNG/JPG）放进 vault 任意位置
2. 属性 `rh-logo: 路径/文件.png`（vault 内相对路径，如 `附件/logo.png`）
3. 预览与 docx 的版头自动居中嵌图（宽 40mm，高按原图比例）
4. 设置了图片后，红色文字机关标志不再渲染，以图为准

### 联合行文：rh-agency 用 / 分隔多机关

多个机关联合行文时，`rh-agency` 用 **`/`**（或全角 `／`）分隔各机关名，红头自上而下每机关一行、上下并列：

```yaml
rh-agency: 中共云溪镇委员会 / 云溪镇人民政府
```

- 字号自适应：按最长机关名估宽，超出版心时自动逐号缩小（下限小标宋 22pt），保证整组红头不超宽
- 机关数量不限；正文标题、署名、版记等其余要素写法不变
- 单机关写法（不带 `/`）行为与旧版完全一致，已有文件零回归

## 十三、版记分页模式（设置项，三态）

GB/T 9704-2012 双面印制规范：版记应置于公文**最后一面**——双面印刷、左侧装订下即偶数页（封底）。设置 → **「版记分页模式」**下拉，三档：

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| **关闭（随正文）** | 版记直接跟在正文后，不单独分节 | 单面打印、短文 |
| **自动（推荐）** | 估算正文能否装进一页：能 → 版记留在第 1 页不拆节；不能 → 拆到偶数页 | 日常公文，一页/多页都正确 |
| **强制偶数页** | 恒拆到偶数页（正文止于偶数页时 Word 自动补空白页） | 坚持版记封底、双面打印 |

**自动模式的一页判定**：正文一页装得下就不拆，避免「一句话公文 + 版记被推到近乎空白的第 2 页」。判定按 GB/T 固定版式估算（A4 版心高 225mm、3 号正文 16pt、行距固定），留 ~1.5% 余量偏向不拆；极端临界处与 Word 实际分页可能差一行，此时建议手动选「强制偶数页」。

**仅影响 docx 导出**：预览 / PDF 打印为流式分页，不适用此规则（需偶数页版记的 PDF，请导出 docx 后用 Word/WPS 转 PDF）。

**页码两分法自动实现**（自动/强制拆节时生效）：页码包在条件域里，由 Word/WPS 打开文档时逐页求值——出现空白页（正文止于偶数页）：空白页与版记页**均不编页码**（符合国标）；无空白页（正文止于奇数页）：版记页**正常编页码**（符合国标）。原理：正文末段打书签，页脚用 `IF { PAGE } > { PAGEREF 书签 }` 判断当前页是否越过正文末页；Word 打开时自动刷新域（`updateFields`）。兜底：若阅读器不支持域求值，退化为普通页码显示。

**页码空一字**：GB/T 9704 §7.5 页码编排要求「单页码居右空一字、双页码居左空一字」——docx 页脚段按页码字号整字宽精确空字，单页（右）与双页（左）分别生效；预览打印 PDF 同源一致。

## 十四、落款对齐与结构层位置（设置项）

公文各尾部要素相对版心的位置，以「**字**」为单位描述（1 字 ≈ 该行字号宽度；3 号正文 16pt 一字、版记四号 14pt 一字）。设置 → RedQuill 内两处：

### 落款（署名 + 成文日期）：对齐三档 + 左/右空

「落款对齐」下拉决定署名与成文日期的水平方式，GB/T 9704 默认右对齐：

| 对齐 | 含义 | 生效的配套输入 |
| --- | --- | --- |
| **右对齐（GB/T，右空N字）** | 落款靠右排：日期距右版心 N 字，署名以日期为轴居中（默认 N=4，国标） | 落款右空（字） |
| **水平居中** | 署名与日期各自相对版心居中 | — |
| **左对齐（左空N字）** | 落款从左侧起排，距左版心 N 字（0=顶格） | 落款左空（字） |

- 「落款右空（字）」（仅右对齐生效）：相对**右版心**往左退的字数。GB/T 规定 4 字（默认）；实务 2 字更贴右；0=紧贴右边距
- 「落款左空（字）」（仅左对齐生效）：相对**左版心**往里缩的字数，0=顶格左对齐
- 切换对齐方式时，不相干的输入框自动禁用；范围 0-12，预览与 docx 导出同步生效

### 结构层位置：五个左空/右空

「结构层位置」组内 5 个输入框，均按 GB/T 9704 默认：

| 设置项 | 控制要素（frontmatter 键） | 默认（国标） |
| --- | --- | --- |
| 附注左空（字） | `rh-notes` 附注行（联系人等） | 2 |
| 附件说明左空（字） | `rh-attachments` 附件说明行 | 2 |
| 版记抄送/印发机关左空（字） | `rh-cc` 抄送行、`rh-printOrg` 印发机关行（按四号字宽计，渲染为全角空格起排，不缩版记分隔线） | 1 |
| 版记印发日期右空（字） | `rh-printDate` 印发日期行（制表位右缘，按四号字宽计） | 1 |
| 版记印发份数右空（字） | `rh-printCopies` 印数行 | 3 |

### 成文日期印章（rh-seal）

需要加盖公章时，把印章图片（PNG/JPG，**透明底**最佳）放进 vault，属性写 `rh-seal: 附件/机关章.png`：

- 导出 docx 时印章以**浮图**方式压在成文日期上（骑年盖月：章中轴比日期中心略右移压向「年」字、章下缘压住日期行下部），Word/WPS 打开即见，文字与章可重叠
- 预览面板同源叠加（`position:absolute`），打印存 PDF 同样带章
- 章直径按国标**42mm** 渲染；有 `rh-date` 才盖（无日期不渲染，避免悬空）
- 印章图只作定位校验用样例——实际盖章文件请用本单位真实印章扫描件/电子章图替换
- CLI 同样支持：`rh-seal` 相对 md 文件所在目录解析，文件缺失时提示「按无章处理」（不阻断导出）

### 落款防孤行

导出 docx 时自动防止三种「孤行」拆散落款：

- 正文**最后一个段落**与落款保持同页（keepNext）——避免落款整块被挤到下一页顶头
- **署名**与成文日期保持同页（有 `rh-date` 时署名段 keepNext）
- 正文末段若恰在页底，整组（末段 + 署名 + 日期）一起顺延到下一页，不出现「署名孤悬页首 / 日期孤行跑页」

预览按浏览器流式分页近似（以 docx/Word 实际分页为最终真相）。

## 十五、设置备份与同步

RedQuill 全部设置（含对内置预设的改动、自建预设、落款/结构层位置参数、通用 autoClean 开关）可一键导出为 JSON 文件，随库备份或在换机/同事间同步同一套版式：

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 导出 | 设置 → RedQuill → 备份与同步 →「导出 JSON」 | 在 vault 根目录生成 `redquill-settings-<时间戳>.json`（纳入 git/同步盘即可随库备份） |

## 十六、字体说明

docx 只声明字体名、不嵌字体文件：

- **机关电脑**：需安装方正小标宋、仿宋_GB2312、黑体、楷体_GB2312

## 十七、CLI（进阶，调试/批处理用）

输入支持三种：单个 `.md` 文件、**目录**（递归收全部 md）、**最小 glob**（`**`、`*`、`?`）。单文件行为与插件内一致：

```bash
node dist/cli.js input.md                        # 导出同目录同名 docx
node dist/cli.js input.md --check                # 排版体检：只查不导出，输出 JSON 问题清单（有 error 级 exit 2）
node dist/cli.js input.md -o out.docx            # 指定输出
node dist/cli.js input.md --preset gongwen-simple # 指定预设
node dist/cli.js input.md --data data.json       # 用 JSON 提供公文要素/设置
node dist/cli.js input.md --colophon-mode auto   # 版记分页：off/auto/force

# 落款与结构层位置（值域 0-12，越界自动忽略回默认）
node dist/cli.js input.md --signature-align left   # 落款对齐：right/center/left
node dist/cli.js input.md --signature-right 2      # 落款右空 N 字（right 模式）
node dist/cli.js input.md --signature-left 1       # 落款左空 N 字（left 模式）
node dist/cli.js input.md --attach-left 3          # 附件说明左空 N 字
node dist/cli.js input.md --notes-left 1           # 附注左空 N 字
node dist/cli.js input.md --colophon-left 0        # 版记抄送/印发机关左空 N 字
node dist/cli.js input.md --print-right 2          # 版记印发日期右空 N 字
node dist/cli.js input.md --copies-right 0         # 版记印发份数右空 N 字
```

### 多文档归档

```bash
# 批量导出：目录输入，输出到归档目录（保留子目录结构，重名不互盖）
node dist/cli.js 通知/2026/ --out-dir 归档/ --preset gongwen-standard
node dist/cli.js "通知/**/*.md" --out-dir 归档/          # glob 输入同样支持
node dist/cli.js a.md 通知/b.md 笔记/c.md --out-dir 归档/  # 多文件混排

# 批量体检：多文件汇总 JSON（任一 error 级 exit 2）；--table 换人读汇总表
node dist/cli.js 通知/ --check
node dist/cli.js 通知/ --check --table

# 文号台账：扫描全部笔记的 rh-docNumber，报重号/漏号/格式问题
node dist/cli.js 通知/ --ledger                          # stdout 文本表
node dist/cli.js 通知/ --ledger -o 台账.csv              # 登记表（.csv/.md/.txt 按扩展名）
```

- **docx 文件属性**：导出的 docx 自动写入标题（=正文标题）、作者与最后修改者（=发文机关）、描述（=发文字号）——归档后在文件管理器/Finder 可按属性检索、与台账一一对应；普通笔记（无机关/文号）不写多余属性。
- **台账状态判定**：同号两篇互标「重号」；设了发文机关/署名/主送但没有文号的标「漏号」；普通笔记（无公文要素）不误报。文号格式问题（半角括号、缺 `〔年份〕`）单独列出。

CLI flag 优先级高于 `--data` JSON 中同名键；`--check` 与插件内「公文排版体检」是同一引擎：单输入输出 JSON 数组，多输入输出 `{summary, files[]}` 汇总（`--table` 换人读文本）；含问题码/级别/说明/行号，可接 CI 或批处理门禁。自动跳过隐藏目录与 `node_modules`。

## 十八、设置页（双区）

设置 → RedQuill，从上到下分两区：

**通用区**（普通笔记写作）：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 自动净化粘贴 | 关 | 编辑器内粘贴带格式 HTML 自动清洗（见 §四） |

**公文区**（排版预设 / 写作 / 版记 / 落款 / 备份同步）：排版预设（内置「公文·标准」「日常·简洁」，逐项可改、一键重置）、默认发文机关（红头）、版记分页模式三态、落款对齐与结构层位置、备份与同步。设置项刻意收敛——体检规则、面板卡片是定死的出厂集，不做逐项开关（防配置蔓延）。

## 十九、常见问题

| 问题 | 原因与处理 |
| --- | --- |
| 预览没出红头 | frontmatter 没写任何 `rh-*` 属性，或键名拼写错误——写作辅助面板「公文属性表单」最稳 |
| 打开普通笔记也出现公文按钮/被当公文 | frontmatter 误留了 `rh-*` 键（空值不算，非空即命中）；删掉或用「切换公文模式」强制通用 |
| 发文字号没对齐/没居中 | 正常，字号按国标在红线上方居中排；如用了半角括号会收到提醒 |
| docx 里字体不对 | 见「字体说明」，目标机器缺字体 |
| 预览分页与 docx 有细微差异 | 预览是浏览器分页近似，以 docx/PDF 为最终真相 |
| 改了内置预设想还原 | 设置 → 预设 → 该预设「重置」按钮 |
| 体检报「版记要素缺漏」 | 版记须「印发机关 + 印发时间」成对，按提示补 `rh-printOrg` / `rh-printDate` |
| 体检报「属性键拼写错误」 | 键名拼错或不存在，按提示的最近键名改正；用表单最不易拼错 |
| 一键修复会不会改坏代码块/链接 | 不会。代码围栏、行内 code、URL、md 链接在扫描与修复时整段保护（§五 保护机制），断言覆盖 |
| 为什么数字不加空格（2026年 / 3.5） | 中文与字母之间补空格是惯例；数字与中文在年份、数量、版本里语义一体，加了反而散 |
| 面板体检每次击键都扫，大文件卡吗 | 面板开着才扫，200ms 防抖合并；几万字符逐行正则在毫秒级 |
| 和 Linter / 各类 md 格式化插件什么关系 | Linter 做「全文规范重排」；RedQuill 通用层只做粘贴净化/八条体检/仪表盘三件小事，围绕中文写作场景，两者不冲突 |
| 换电脑 / 给同事同步版式 | 设置 → 备份与同步 → 导出 JSON，另一台导入（见 §十五） |

### docx 三端兼容（WPS / Word / LibreOffice）

导出 docx 以 **Word 为参照系**（GB/T 9704 排版真相）；WPS 排版引擎与 Word 同源，一般逐像素一致；LibreOffice 引擎独立，打开时的**允许差异**（不视为缺陷）：

1. **字体回落**：docx 只声明字体名、不嵌入字体文件。三端都按本机字体回落到可显示字体。机关电脑装上「方正小标宋/仿宋_GB2312/楷体_GB2312/黑体」即一致。
2. **LibreOffice 页码域**：正文/版记分节的页码是 Word 域。Word/WPS 打开自动求值；LibreOffice 若页码与页序不符，全选 `Ctrl+Shift+F9` 更新域即重算（域求值差异，非版式缺陷）。
3. **分页临界差一行**：三端排版引擎不同，正文末页/版记页在临界长度处可能差一行；以 Word 为准，差一行可接受，差整页属问题。
4. **印章浮图偏移**：印章以浮动锚图压盖（骑年盖月），LibreOffice 对 `wp:anchor` 的 1–2pt 级位置差属正常；判定看章下缘压住日期行、不穿出版心。
5. **行距固定**：三端均支持固定行距；极端字号组合下 LibreOffice 行高可能有 1px 级显示差，可接受。
